## Version note

Targets **Next.js 16** (current stable). Next.js 15 is in maintenance LTS — its support ends 2026-10-21.
The breaking changes from 15 are flagged inline below; do not carry v15 patterns into a v16 codebase.

Upgrade path: `npx @next/codemod@canary upgrade latest`

## App Router File Conventions

```
app/
├── layout.tsx          # Root layout (required)
├── page.tsx            # Home page (/)
├── loading.tsx         # Loading UI (Suspense)
├── error.tsx           # Error boundary
├── not-found.tsx       # 404 page
├── default.tsx         # REQUIRED for every parallel route slot in v16 (build fails without it)
├── (auth)/             # Route group (no URL impact)
│   ├── login/page.tsx  # /login
│   └── signup/page.tsx # /signup
├── api/
│   └── route.ts        # API handler
└── _components/        # Private folder (not routed)

proxy.ts                # Root level. Replaces middleware.ts in v16.
```

## Server Components (Default)

## Async request APIs (BREAKING in v16)

`params`, `searchParams`, `cookies()`, `headers()` and `draftMode()` are async. Synchronous
access was removed — it is not a deprecation warning, it fails.

```typescript
// Page props
export default async function Page({
  params,
  searchParams,
}: {
  params: Promise<{ id: string }>;
  searchParams: Promise<{ q?: string }>;
}) {
  const { id } = await params;
  const { q } = await searchParams;
  return <Detail id={id} query={q} />;
}

// Request APIs
import { cookies, headers, draftMode } from "next/headers";

const cookieStore = await cookies();
const token = cookieStore.get("token");

const headerList = await headers();
const ua = headerList.get("user-agent");
```

## Server Actions

```typescript
// app/actions.ts
"use server";

import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";

export async function createUser(formData: FormData) {
  const name = formData.get("name") as string;

  await db.users.create({ data: { name } });

  revalidatePath("/users");
  redirect("/users");
}

// Usage
<form action={createUser}>
  <input name="name" required />
  <button type="submit">Create</button>
</form>
```

## Caching APIs

Pick by semantics, not habit:

| Need | Use | Where |
|---|---|---|
| User must see their own write immediately | `updateTag(tag)` | Server Actions only |
| Invalidate cache, tolerate eventual consistency | `revalidateTag(tag, profile)` | Anywhere |
| Refresh uncached data only, leave cache alone | `refresh()` | Server Actions only |
| Invalidate by path | `revalidatePath(path)` | Anywhere |

```typescript
"use server";
import { updateTag, revalidateTag, refresh } from "next/cache";

// Read-your-writes: user sees the change right away
export async function updateProfile(userId: string, profile: Profile) {
  await db.users.update(userId, profile);
  updateTag(`user-${userId}`);
}

// SWR invalidation. The profile argument is REQUIRED in v16 —
// the single-argument form is deprecated.
revalidateTag("blog-posts", "max");     // 'max' is the recommended default
revalidateTag("news-feed", "hours");
revalidateTag("products", { expire: 3600 });

// Refresh uncached data (notification counts, live metrics)
export async function markRead(id: string) {
  await db.notifications.markAsRead(id);
  refresh();
}
```

## Cache Components (opt-in)

Caching is explicit in v16: all dynamic code runs at request time unless you opt in.

```typescript
// next.config.ts
const nextConfig = { cacheComponents: true };
export default nextConfig;
```

```typescript
// Cache a page, component, or function. Cache keys are generated by the compiler.
async function ProductList() {
  "use cache";
  const products = await db.products.findMany();
  return <List items={products} />;
}
```

Replaces the removed `experimental.ppr` and `experimental.dynamicIO` flags.

## Route Handlers (API)

```typescript
// app/api/users/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(request: NextRequest) {
  const users = await db.users.findMany();
  return NextResponse.json(users);
}

export async function POST(request: NextRequest) {
  const body = await request.json();
  const user = await db.users.create({ data: body });
  return NextResponse.json(user, { status: 201 });
}
```

## proxy.ts (was middleware.ts — BREAKING in v16)

Same logic, new filename and function name. Runs on the Node.js runtime.
`middleware.ts` still works for Edge-runtime cases but is deprecated and will be removed.

```typescript
// proxy.ts (root level)
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export default function proxy(request: NextRequest) {
  const token = request.cookies.get("token");

  if (!token && request.nextUrl.pathname.startsWith("/dashboard")) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*"],
};
```

## Metadata

  params,

## Removed in v16 — do not generate these

| Removed | Use instead |
|---|---|
| `next lint` | Biome or ESLint directly (`next build` no longer lints) |
| `serverRuntimeConfig`, `publicRuntimeConfig` | Environment variables (`.env`) |
| `experimental.ppr`, `experimental.dynamicIO` | `cacheComponents: true` |
| AMP support (`useAmp`, `config = { amp: true }`) | — (fully removed) |
| `images.domains` | `images.remotePatterns` |
| `next/legacy/image` | `next/image` |
| Sync `params` / `cookies()` / `headers()` | `await` them |

## Defaults that changed

- **Turbopack** is the default bundler. Opt out with `next dev --webpack` / `next build --webpack`.
- **React Compiler** is stable but NOT on by default: set `reactCompiler: true` (expect slower builds, it uses Babel).
- `images.minimumCacheTTL`: 60s → 14400s. `images.qualities`: `[1..100]` → `[75]`.
- Requires Node.js 20.9+ and TypeScript 5.1+.
